# Подробный конспект о ключевом слове `var` в C#

#### 1. Основы `var`

**`var`** — не тип данных, а **ключевое слово** для **неявной типизации** (implicit typing). Оно позволяет компилятору автоматически вывести тип переменной из выражения инициализации.

**Важно:** тип определяется **на этапе компиляции**, а не во время выполнения. После компиляции переменная имеет строго определённый тип.

#### 2. Правила использования

**Обязательные условия:**
* переменная должна быть **инициализирована** при объявлении;
* инициализатор не может быть `null` без явного указания типа;
* выражение инициализатора должно позволять однозначно определить тип.

**Примеры корректного использования:**
```csharp
var number = 10;           // int
var text = "Hello";       // string
var flag = true;          // bool
var list = new List<int>(); // List<int>
```

**Примеры некорректного использования:**
```csharp
// Ошибка: нет инициализатора
var x;

// Ошибка: null не определяет тип
var y = null;

// Ошибка: неоднозначность
var z = SomeMethod(); // если SomeMethod() может возвращать разные типы
```

#### 3. Как работает вывод типа

Компилятор анализирует выражение справа от `=` и определяет точный тип:

```csharp
var a = 5;                    // int
var b = 3.14;             // double
var c = 3.14f;           // float
var d = "text";           // string
var e = new[] {1, 2, 3}; // int[]
var f = new { Name = "John", Age = 25 }; // анонимный тип
```

#### 4. Типы, которые можно выводить с помощью `var`

* **Встроенные типы:** `int`, `double`, `string`, `bool` и т. д.
* **Массивы:**
  ```csharp
  var numbers = new[] {1, 2, 3, 4, 5}; // int[]
  var names = new[] {"Alice", "Bob"};     // string[]
  ```
* **Коллекции:**
  ```csharp
  var list = new List<string>();     // List<string>
  var dict = new Dictionary<int, string>(); // Dictionary<int, string>
  ```
* **Анонимные типы:**
  ```csharp
  var person = new { Name = "Alice", Age = 30 };
  // Создаётся анонимный тип с свойствами Name (string) и Age (int)
  ```
* **Типы из LINQ‑запросов:**
  ```csharp
  var query = from s in students
              where s.Age > 18
              select new { s.Name, s.Grade };
  ```

#### 5. Ограничения `var`

**Нельзя использовать, если:**
* тип не может быть однозначно определён компилятором;
* переменная инициализируется `null`;
* требуется явное указание интерфейса или базового класса;
* нужно объявить поле класса без инициализатора.

**Пример ограничения:**
```csharp
// Не сработает: компилятор не знает, какой тип создать
var items = null;

// Правильно: явно указываем тип
List<string> items = null;
```

#### 6. `var` и LINQ

Особенно полезен при работе с LINQ, где типы могут быть сложными:
```csharp
var query = from customer in customers
            where customer.Orders.Count > 5
            select new
            {
                customer.Name,
                OrderCount = customer.Orders.Count
            };
// Тип результата — анонимный
```

#### 7. `var` с обобщениями (generics)

Упрощает код при создании обобщённых типов:
```csharp
// Без var (многословно)
Dictionary<string, List<int>> complexDict = new Dictionary<string, List<int>>();

// С var (компактно)
var complexDict = new Dictionary<string, List<int>>();
```

#### 8. Отличия от динамической типизации

**Важно не путать `var` с динамической типизацией (`dynamic`):**

| `var` | `dynamic` |
|-------|-----------|
| Тип определяется на этапе компиляции | Тип определяется на этапе выполнения |
| Статическая типизация | Динамическая типизация |
| Ошибки типов выявляются при компиляции | Ошибки типов могут возникнуть во время выполнения |
| Высокая производительность | Пониженная производительность из‑за проверки типов во время выполнения |

**Пример:**
```csharp
var staticVar = "text";    // Тип string известен компилятору
dynamic dynamicVar = "text"; // Тип определяется во время выполнения
```

#### 9. Практические примеры использования

**Пример 1: работа с коллекциями**
```csharp
var numbers = new List<int> {1, 2, 3, 4, 5};
var squares = numbers.Select(n => n * n); // IEnumerable<int>
foreach (var square in squares)
{
    Console.WriteLine(square);
}
```

**Пример 2: анонимные типы**
```csharp
var person = new
{
    Name = "Alice",
    Age = 25,
    City = "Moscow"
};
Console.WriteLine($"{person.Name}, {person.Age} лет, {person.City}");
```

**Пример 3: сложные типы**
```csharp
var complexObject = new
{
    Id = 123,
    Data = new Dictionary<string, List<double>>
    {
        ["prices"] = new List<double> {10.5, 20.3, 15.7}
    }
};
```

#### 10. Рекомендации по использованию

**Использовать `var` рекомендуется, когда:**
* тип очевиден из инициализатора;
* используется с LINQ и анонимными типами;
* упрощает чтение кода, убирая избыточность;
* создаётся экземпляр обобщённого типа с длинными параметрами.

**Лучше явно указывать тип, когда:**
* это улучшает читаемость кода;
* тип неочевиден из инициализатора;
* требуется указать интерфейс вместо конкретной реализации;
* переменная инициализируется методом, возвращающим базовый тип;
* в команде принят стандарт явного указания типов.

**Примеры:**
```csharp
// Хорошо: тип очевиден
var count = 10;
var message = "Hello";

// Лучше явно: тип неочевиден
IList<string> names = GetNames();

// Хорошо: упрощает длинные обобщённые типы
var dictionary = new Dictionary<string, List<Tuple<int, decimal>>>();

// Лучше явно: требуется интерфейс
IEnumerable<int> numbers = GetNumbers();
```

#### 11. Особенности и нюансы

* **Отладка:** в отладчике можно увидеть выведенные типы.
* **Рефакторинг:** изменение инициализатора может изменить тип переменной.
* **Читаемость:** в некоторых случаях явное указание типа улучшает понимание кода.
* **Совместимость:** `var` доступен с C# 3.0 (2007 год).

---

#### Краткий итог

* `var` — ключевое слово для неявной типизации, а не тип данных;
* тип выводится компилятором на основе инициализатора;
* требует обязательной инициализации при объявлении;
* особенно полезен с LINQ, анонимными типами и обобщениями;
* не является динамической типизацией (в отличие от `dynamic`);
* использование должно быть обоснованным — баланс между компактностью и читаемостью кода.
